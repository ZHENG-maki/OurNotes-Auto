# 自动演奏分析与随机模式接入

分析日期：2026-10-28。基于上游 master 的 d9fcd99（版本 0.2.0）。
本分支为 ZHENG-maki 修改版，保留原作者 ChissaQAQ 署名及免费开源声明。

## 自动演奏如何工作

它按已知谱面定时执行，不会在每个音符落下时重新识别并决定点击。

1. `runner.py:Runner.play_once` 导航至乐队确认页，调用 `_identify` 得到曲目 ID、难度。
2. `nav/navigator.py:selected_song` 连续读取曲名、难度、等级，并可使用封面辅助识别；`runner.py:identify_song` 与曲目目录匹配。
3. `charts/bdon.py` 下载/读取缓存谱面，`charts/parser.py` 根据节拍和 BPM 变化转换为毫秒时间，解析点击、划动和长条。
4. `planner.py:Planner` 把音符转换成 DOWN/MOVE/UP 手势，分配多点触控编号、处理邻近音符冲突；长条默认每 8ms 采样一次。
5. `player/sync.py:NoteTracker` 跟踪首音符前沿，以指数运动模型推算到达判定线的时刻。模型为 `t = a + τ·ln(y-y_h)`，流速 5.00 默认 τ=0.835s。加权拟合、离群点处理、渲染网格对齐后得到谱面起点 t0。
6. `player/executor.py:Executor` 在 `t0 + (event.t_ms + offset_ms)/1000` 发出事件；0.5ms 内事件合批，过期 MOVE 可跳过，DOWN/UP 保留。
7. 默认 `device/minitouch.py` 经 adb 管道写触控设备，flush 提交一批；失败可回退 MuMu IPC。截图由 `device/mumu.py` 的 MuMu IPC 提供。
8. `player/guard.py` 后台检查演奏画面和生命值，`player/monitor.py` 可记录连击截图供演奏后 OCR 定位断连。
9. `runner.py:_record` 读结算，`records.py` 根据 FAST/SLOW 学习 offset：SLOW 较多则提前，FAST 较多则推迟；另有按谱面修正。

整首演奏主要使用首音符确定的一条绝对时间轴，演奏中截图监视并不持续校正歌曲时钟。

## 已完成的稳定性修复

1. 连击截图卡顿后跳过已错过的采样时刻，不再连续补做截图，避免恢复阶段额外抢占截图接口。
2. 执行器最后一次等待结束后再检查停止信号，避免用户停止或 guard 中断后仍多发一批触控。
3. 出现截图卡顿或 hold 丢弃事件的局只记录结果，不用其 FAST/SLOW 更新全局或谱面 offset，减少不稳定样本对后续局的干扰。

验证：`python -m pytest tests/test_executor.py tests/test_monitor.py tests/test_runner.py -q`，98 项通过。
测试覆盖 10/100/650ms 截图耗时、等待期间停止，以及卡顿/hold 后不学习偏移。
尚未在模拟器实机演奏验证，不能据此宣称 AP 率提升。原安装目录没有覆盖。

## 新随机歌曲模式的接入点

目前的 `loop.song_mode=random` 只是让脚本在普通选曲页点击随机按钮，仍假定开始前能读取最终曲目。
这与游戏进入新模式后才揭晓歌曲的流程不同。

需要新增独立入口，建议状态流为：

`等待最终选曲 → 读取并确认实际曲目/难度 → 准备谱面 → 等待启动并同步首音符 → 执行`

实现取决于实际页面：

- 若最终曲目先在确认页显示：等待该页稳定后读曲目，下载谱面；通过新模式自己的开始流程衔接同步。
- 若只有加载画面揭晓：先缓存候选谱面；在加载画面尽早 OCR 实际曲名/难度，随即准备计划和同步。不能把旧确认页坐标当成加载页坐标。
- 若加载前歌曲没有确定：不能使用先前选中的歌曲，也不能只延长旧导航的 90 秒超时。
- 若模式不支持暂停重试，应禁用原有自动暂停重试恢复流程，失败后等待本局结束。
- 等待过程中应支持停止，不能把长时间等待当成未知画面卡死而重启游戏；也不应调用会自动退出新模式的旧导航。

还需确认新模式名称、最终曲名/难度显示页面、是否自动开始，以及揭晓后到首音符的时间。
目前没有这些页面的截图/OCR 样本，因此尚未实现或验证新模式识别，也未新增一个仅改名字的伪支持开关。

## 后续优化顺序

先完成新模式识别和等待状态机，用真实页面样本测试识别结果和超时/停止；再记录 backend/flush 耗时，以区分发送端、传输端与游戏帧的延迟。
如需处理演奏中时间漂移，再评估基于后续音符轨迹的低频校验及平滑调整，避免一次截图异常造成全曲时间轴突跳。

## 已新增的手动指定入口

已新增「自动演出」任务及 `auto-play` 命令：从歌曲下拉列表选择实际歌曲与难度后，先准备谱面，再等待首音符出现并同步，随后仅按谱面演奏，不再截图、识别暂停按钮或监视生命值/连击。无需识别新模式的曲名页。具体操作见 [自动演出使用说明](自动演出使用说明.md)。这一入口不代表已经支持随机结果的自动识别。
